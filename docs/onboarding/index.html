EXECUTION CONTROL

What a pause holds.

Events, not instructions.The gate holds a thread at its next event. A loop without an event runs on.

Threads, not coroutines.A held coroutine keeps its thread. The other coroutines of that thread wait with it.

Time isn’t held.A timeout can fire on release. A slower program interleaves differently.

A pace is for each sequence.The gate paces parallel coroutines independently. No global queue exists.

The trace records hold durations and setting changes, with no blocking event for a hold. When the last controller disconnects, the program resumes at the configured pace and removes subtree settings.

06 / MAKE A CHANGE

Four rules.

Read DESIGN §12 ↗ before changing behavior.

01

Hooks never throw into the program.

Guard against reentrancy and catch Throwable. The runtime is Java without dependencies.

Hooks.java ↗
02

Change both trace implementations.

Update TraceEncoder/Wire, Trace.kt and the format document. Check the result against a real-agent trace.

TRACE_FORMAT.md ↗
03

The drawing invariant is strict.

Boxes never overlap. Two lines never share a segment. Lines cross only at right angles. The checker judges shapes and takes nothing from the router.

InvariantChecker.kt ↗
04

Wording and logic have one place each.

The wording of events and nodes is in Labels.kt. GUI logic goes in view/ or source/, and composables stay thin. Plugin task state must survive the configuration cache.

CLAUDE.md ↗
Rules for instrumentation and the gate ＋

Class loading: use COMPUTE_MAXS, branch-free patches and no frame recomputation. Warm up transformer paths before installation. Retransformed JDK classes can’t change shape.

Hook paths: no lambdas and no invokedynamic. Kotlin objects arrive as Object, and the runtime reaches them through method handles.

The gate: find all nodes before Pace.await. Read state and take locks after it. The wait is Thread.sleep, because a park consumes the thread’s park permit. Never wait in Tracer.emit.

Plugin contracts: change properties, source indexes and native probe paths on both sides. AgentConfigTest checks the properties and index.

Limits of a trace ＋

Development tool: traces contain stacks and context values verbatim. Coroutine-heavy code runs several times slower. Don’t combine coroutine agents.

Platforms: only macOS arm64 has run end to end. Windows is untested, and its native probe build isn’t scripted. Without the probe, the agent reports everything except monitor contention.

Capture: executor task nodes, virtual thread mount and pin events, Flow and channel semantics, and file I/O aren’t implemented. The agent traces only the first copy of kotlinx.coroutines in a JVM. A coroutine started with startCoroutineUninterceptedOrReturn and a completion of its own can stay unseen. Generators are hidden.

Reader and sources: recorded files are read once. Use live sessions to follow a JVM. Custom KMP JVM targets lack dependency source indexes.
